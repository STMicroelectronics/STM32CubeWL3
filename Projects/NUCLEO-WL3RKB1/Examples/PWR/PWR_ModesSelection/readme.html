PWR_ModesSelection Example Description

How to select a power mode through USART1 and configure the system to measure the MCU current consumption. The system clock is set to 64 MHz.

SelectionConfiguration
1Run at 64 MHz, idle loop executing from Flash
2Sleep at 64 MHz, no periodic wakeup
3DeepStop, LSI and LSE off, SRAM retained
4DeepStop, LSI on, LSE off, SRAM retained, RTC off
5Shutdown, BOR off
6Shutdown, BOR on
7Ultra DeepStop, BOR off
8Ultra DeepStop, BOR on

After a valid selection, the application waits for 5 seconds, then disables the USART, turns off the LEDs and prepares the GPIOs for measurement. SysTick, interrupts, wakeup sources and debug retention are disabled. External RESET is required to return to the menu; the USER push-buttons and serial input do not wake up the MCU.

  • All LEDs off: current measurement configuration active.
  • LD3 ON: configuration failed or a reset-only power mode unexpectedly returned; the system enters an infinite loop and the measurement is not valid.

Notes

  1. RC64MPLL supplies the 64 MHz system clock, with HSE enabled for Run and Sleep. SMPS uses the board startup configuration. No radio, RTC, watchdog or application timer is initialized. LSI is enabled only for selection 4; LSE remains off. DeepStop uses the startup SRAM retention configuration; Shutdown does not retain SRAM. Ultra DeepStop is an additional low-power mode supported by STM32WL3R devices.
  2. Measure the MCU supply path described in the board user manual, not the complete board USB input current. Use a suitable instrument range and burden voltage. Disconnect ST-LINK/SWD, the virtual COM port and external circuitry during the 5-second delay while maintaining a valid MCU supply. Avoid back-powering through GPIOs. Wait for the current to settle.
  3. Match datasheet supply voltage, temperature, SMPS, clock, BOR, SRAM, GPIO and wakeup conditions before comparing current. The Run idle loop may differ from the datasheet workload. Typical values are not maximum limits. Formal electrical validation against the datasheet remains pending.
  4. SWD pin functions are disabled during measurement. To reprogram, connect under reset. The menu remains active until a valid selection is received.
  5. HAL_Delay() requires a 1 ms SysTick time base during initialization and the preparation delay. SysTick is deliberately stopped for measurement.
  6. The MSP lowPowerIOSetup() helper is called after console shutdown, not from HAL_MspInit(), so the menu remains available until measurement preparation.
  7. This example is manually maintained; no CubeMX .ioc file is provided.

Hardware and Software environment

  • STM32WL3RKBVx devices, STMicroelectronics NUCLEO-WL3RKB1 board.
  • EWARM, MDK-ARM and STM32CubeIDE projects are provided.
  • USART1 virtual COM port: PA1 (TX), PB14 (RX). Refer to the board user manual for solder-bridge routing and MCU current-measurement connections.
  • Terminal: 115200 baud, 8 data bits, no parity, 1 stop bit, no flow control.

How to use it ?

  • Open your preferred toolchain project for NUCLEO-WL3RKB1.
  • Rebuild all files and load your image into target memory.
  • Open the terminal, then run or reset the example.
  • Send one menu digit. No Enter key is required; CR and LF are ignored. Invalid input is reported and selection remains active.
  • Disconnect debug and serial links during the 5-second delay, keeping the MCU powered as described in the Notes.
  • Measure the settled MCU supply current.
  • Apply an external RESET to select another configuration.
